# Shared HiFi k-mer evaluation

Four individual k=21 Meryl counts are generated from `../../inputs/SRR26381151.fastq` through `SRR26381154.fastq`; `meryl union-sum` creates the single `reads/all_hifi.k21.meryl` database used for all three comparisons. This preserves multiplicities across all four runs. Merqury is run separately for the hifiasm primary, Verkko combined `assembly.fasta`, and the complete NCBI GRCr8 RefSeq genome. Results are written under `results/<assembly>/` and `results/merqury_summary.tsv`. The completeness estimate uses Merqury's data-derived solid-kmer threshold, which is recorded in each result directory.

The NCBI GRCr8 download is checked against NCBI's MD5 manifest and then gzip-tested. Its sequence identifiers and lengths are checked against those in the previous minimap2 reference index input; this does not prove that the old indexed reference is byte-identical to the new download. The short-read/HiFi, ONT and Hi-C materials are associated with the same inbred strain but do not have verified same-individual provenance. Merqury QV is a read-kmer-based estimate, sensitive to read errors, k-mer filtering, heterozygosity and sample differences; lack of a read k-mer is not alone proof of an assembly error. Spectra and per-sequence QV files should be interpreted alongside mapping ambiguity and copy-number differences.

Jobs: 2871273 builds the read database (32 CPUs, 192 GiB, up to 7 days); 2871274 retrieves/validates the reference (2 CPUs, 4 GiB, up to 2 days); 2871275 runs all three Merqury evaluations sequentially after both succeed (32 CPUs, 192 GiB, up to 7 days). Scripts and logs are in `scripts/` and `logs/`.
